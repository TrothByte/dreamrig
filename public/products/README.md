# Изображения товаров

Кладём фотографии сюда. Каждый товар — по номеру `№` из таблицы в
[`docs/product-photos.md`](../../docs/product-photos.md):

- первый кадр: `public/products/<N>.jpg`;
- дополнительные кадры: `public/products/<N>-2.jpg`, `<N>-3.jpg` … (до 4 кадров на товар).

Пример для товара № 42 с тремя фото:

```
public/products/42.jpg
public/products/42-2.jpg
public/products/42-3.jpg
```

Входные файлы можно класть как `<N>.jpg` или `<N>-1.jpg`, а также в `.png`/`.webp` — затем запустить
нормализацию и сжатие:

```
pwsh scripts/optimize-product-photos.ps1
```

Скрипт приводит имена к каноническому виду, конвертирует PNG/WebP в JPEG, ограничивает ширину 1000 px
и сжимает до качества ~78.

Пока файла нет — на карточке показывается штатный графический visual (заглушка не ломается).
Сайт подхватит фото автоматически после добавления файлов.

## Про объём репозитория и сжатие

- Да, сжатые фото нормально пушить на GitHub. Рекомендации: JPEG (или WebP), ширина ~1000 px,
  качество 70–80 — ориентир 80–200 КБ на файл.
- 193 товара даже по 2–3 кадра (~50–80 МБ суммарно) — допустимо для GitHub Pages; репозиторий
  остаётся удобным, если держать суммарный размер до ~100 МБ и не коммитить оригиналы в PNG.
- Один файл больше 100 МБ GitHub не примет — при наших размерах это неактуально.
- Git LFS для Pages не подходит (Pages не раздаёт LFS-файлы), поэтому обычный push — правильный путь.
